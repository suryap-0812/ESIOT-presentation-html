1. Introduction and prerequisites

An accelerometer measures acceleration along one or more axes. Most compact modern devices use MEMS (micro-electro-mechanical systems): a microscopic proof mass is suspended by compliant structures. Acceleration causes relative displacement, which is converted into an electrical signal—often capacitance change—then conditioned and digitized.

In an Arduino project, the microcontroller reads this signal, converts raw counts or voltage to physical units, and uses the result for tilt estimation, motion detection, vibration monitoring or event classification.

Why it matters

Accelerometers bridge the physical world and embedded computation. They appear in phones, wearables, vehicle systems, industrial monitoring, robotics and IoT nodes. Their output also illustrates core ECE concepts: transduction, analog conditioning, ADC resolution, sampling, noise, calibration and digital communication.

Prerequisites

  • Voltage, current and ground reference
  • Ohm’s law and basic circuits
  • ADC resolution and sampling
  • Arduino digital/analog I/O
  • Basic vectors and trigonometry

Key terminology

  • g: standard gravity, approximately 9.80665 m/s²
  • Sensitivity: output change per unit acceleration (e.g. mV/g)
  • Offset/bias: output at nominal zero acceleration
  • Full-scale range: measurable acceleration span
  • Bandwidth: frequency range over which response is specified
  • ADC: analog-to-digital converter

3. Working principle: step by step

  1. Acceleration acts on the proof mass. In a simplified spring–mass model, inertial force is proportional to mass and acceleration.
  2. The mass moves relative to the frame. A suspension provides a restoring force. In capacitive MEMS, motion changes the capacitance between structures.
  3. The sensor converts the change to an output. Integrated circuitry amplifies and filters the signal. Digital sensors also sample it with an internal ADC.
  4. Arduino acquires the reading. For analog sensors, analogRead() returns an ADC code. For digital sensors, software reads the appropriate registers over I²C/SPI.
  5. Firmware calibrates and interprets it. Convert code to volts or counts to g, subtract measured bias if calibrated, filter noise, then estimate tilt or detect motion.

Mechanical model

Finertial = m a;   Fspring = −k x

For a quasi-static ideal spring–mass model, balancing force magnitudes gives x ≈ (m/k) a. Here m is proof-mass (kg), k is effective spring stiffness (N/m), a is acceleration (m/s²), and x is displacement (m). Real MEMS devices require damping, electrostatic geometry, feedback and circuit effects for a complete model.

Static tilt estimate

When the device is stationary or moving slowly enough that linear acceleration is negligible, gravity’s components can estimate orientation. One common convention is:

θx = atan2(ay, az) × 180/π

The exact axis/sign convention depends on how the sensor is mounted. Accelerometers alone cannot reliably separate gravity from sustained linear acceleration; dynamic orientation often uses gyroscope fusion.

Illustrative Arduino sketch — generic analog sensor

const int X_PIN = A0;
const int Y_PIN = A1;
const int Z_PIN = A2;

// Replace these with values from the sensor datasheet
// and calibration measurements.
const float VREF = 5.0;       // ADC reference in volts
const float ADC_MAX = 1023.0; // 10-bit Uno ADC code maximum
const float ZERO_G_V = 1.65;  // illustrative only
const float SENS_V_PER_G = 0.300; // illustrative only

float readG(int pin) {
  int raw = analogRead(pin);
  float volts = raw * VREF / ADC_MAX;
  return (volts - ZERO_G_V) / SENS_V_PER_G;
}

void setup() {
  Serial.begin(115200);
}

void loop() {
  float ax = readG(X_PIN);
  float ay = readG(Y_PIN);
  float az = readG(Z_PIN);

  Serial.print("ax(g)="); Serial.print(ax, 3);
  Serial.print(", ay(g)="); Serial.print(ay, 3);
  Serial.print(", az(g)="); Serial.println(az, 3);
  delay(100);
}

The constants above are examples only—not universal sensor specifications. Replace them with the exact sensor’s zero-g output, sensitivity and ADC reference, then calibrate. The code assumes a 10-bit ADC with codes 0–1023.

Operating modes and practical conditions

  • Static / low-frequency: gravity can support tilt estimation if dynamic acceleration is small.
  • Dynamic: captures motion and vibration; sampling rate must exceed twice the highest frequency of interest in theory, with practical margin and anti-alias filtering.
  • Interrupt mode: sensor may signal motion or data-ready events, reducing continuous polling.
  • Calibration: determine offset and scale; a six-position calibration can estimate bias and scale for each axis.

Common misconceptions

  • An accelerometer is not a gyroscope: it measures acceleration, not angular velocity.
  • Raw ADC counts are not automatically units of g.
  • A resting sensor does not necessarily output 0 g on all axes.
  • Higher range usually trades sensitivity/resolution per g for headroom.
  • Filtering reduces noise but introduces delay and may hide fast events.

4. Equations and derivations

4.1 ADC code to voltage

Vin ≈ D × Vref / (2N − 1)

D is the digital code (0 to 2N−1), N is ADC resolution in bits, and Vref is the ADC reference in volts. This endpoint-scaled formula is convenient for ideal unipolar ADC conversion; actual transfer conventions, quantization and reference tolerances matter. For an ideal N-bit ADC, the LSB step is approximately Vref/2N.

4.2 Voltage to acceleration (analog sensor)

a (g) = (Vout − V0g) / S

Vout is measured output (V), V0g is zero-acceleration bias (V), and S is sensitivity (V/g). Convert to SI units with a (m/s²) = a (g) × 9.80665. Sign indicates direction relative to the sensor axis convention.

4.3 Combining ADC and sensor scale

a (g) ≈ [D × Vref/(2N−1) − V0g] / S

Derived by substituting the ADC voltage estimate into the analog sensor transfer relation. Assumes a linear response and known reference, offset and sensitivity.

4.4 Quantization and effective acceleration step

ΔV ≈ Vref/2N;   Δa ≈ ΔV/S

For a 10-bit ADC and 5 V reference, the nominal step is 5/1024 ≈ 4.883 mV. If sensitivity is 300 mV/g, the ideal code step is about 0.0163 g/count. Actual effective resolution is worse when noise, reference error and sensor noise dominate.

4.5 Magnitude of acceleration vector

|a| = √(ax² + ay² + az²)

Use all axes in the same units. At rest, magnitude is approximately 1 g after calibration, subject to noise, alignment and bias.

4.6 Sampling and aliasing

fs > 2 fmax   (Nyquist lower bound)

fs is sample rate (samples/s) and fmax is the highest frequency in the signal of interest. Real systems require anti-alias filtering and a practical margin above the theoretical lower bound.

4.7 Sensitivity in mV/g

S = ΔV / Δa

For example, if output changes by 0.60 V over a measured acceleration change of 2 g, sensitivity is 0.30 V/g = 300 mV/g. Do not infer sensitivity from a single point unless offset is already known.

5. Solved numerical problems

Example 1 — ADC code to voltage (Easy)

Given: 10-bit ADC, 5.00 V reference, code D = 512. Find: approximate input voltage.

  1. Use V ≈ D × Vref / 1023.
  2. Substitute: V ≈ 512 × 5.00 / 1023.
  3. V ≈ 2.502 V.
Answer: approximately 2.50 V. The result is near half-scale; exact code-to-voltage interpretation depends on the ADC transfer convention.

Example 2 — voltage to acceleration (Moderate)

Given: Vout = 1.95 V, zero-g bias V0g = 1.65 V, sensitivity S = 0.300 V/g. Find: acceleration in g and m/s².

  1. a = (Vout − V0g)/S.
  2. a = (1.95 − 1.65)/0.300 = 1.00 g.
  3. a = 1.00 × 9.80665 = 9.81 m/s².
Answer: +1.00 g, or approximately +9.81 m/s² along the sensor’s positive axis.

Example 3 — ADC-limited acceleration step (Moderate)

Given: Uno-style 10-bit ADC, Vref = 5 V, sensitivity = 300 mV/g. Find: ideal acceleration per ADC count.

  1. Voltage step ≈ 5/1024 = 0.0048828 V.
  2. Acceleration step ≈ 0.0048828/0.300 = 0.01628 g/count.
  3. In SI units: 0.01628 × 9.80665 ≈ 0.1597 m/s²/count.
Answer: about 0.0163 g/count (0.160 m/s²/count), before sensor noise and other errors.

Example 4 — GATE-style sampling problem (Difficult)

Question: A vibration monitor must preserve signal components up to 80 Hz. What is the theoretical minimum sample rate, and what sample rate would provide a practical margin?

  1. Nyquist lower bound: fs > 2fmax.
  2. fs > 2 × 80 = 160 samples/s.
  3. A practical choice might be 400 samples/s, provided the sensor bandwidth, processor and anti-alias filter support it.
Answer: strictly greater than 160 samples/s in theory; 400 samples/s is one reasonable engineering choice, not a universal requirement.

How to validate a setup in Multisim / lab

  1. Confirm whether the exact sensor has a supported SPICE model. If not, use a behavioral voltage source representing the datasheet transfer curve and label it as a model.
  2. Set the model equation, for example Vout = V0g + S × a_g, and sweep a controlled acceleration parameter across the intended range.
  3. Check output rails, linearity and expected polarity. Add supply decoupling and realistic output impedance if relevant.
  4. For Arduino acquisition, validate firmware and ADC behavior on the actual board or in an environment that explicitly supports the selected microcontroller.
  5. Compare with a controlled orientation or known calibration setup; do not treat an illustrative curve as measured evidence.

8. Core electronics interview questions

1. What does an accelerometer measure?

It measures specific force along one or more axes. When stationary, gravity contributes to the reading, so an axis aligned with gravity can show approximately ±1 g depending on orientation and sign convention.

2. Explain the MEMS operating principle.

An inertial proof mass moves relative to its frame. A transducer—commonly differential capacitors—converts displacement into an electrical signal; conditioning circuitry maps it to analog voltage or digital data.

3. Why does a stationary sensor show about 1 g?

The sensor responds to support force relative to free fall, commonly described as specific force. At rest, gravity’s projection appears in the sensor axes; vector magnitude is approximately 1 g after calibration.

4. How do you convert an analog reading to g?

Convert ADC code to voltage using the ADC reference and resolution, then use a = (Vout − V0g)/S. Measure or obtain V0g and sensitivity S from calibration/datasheet; do not use generic constants blindly.

5. What causes incorrect acceleration readings?

Likely causes include incorrect supply or logic levels, wrong ADC reference, axis mapping/sign errors, uncalibrated offset, sensor saturation, electrical noise, loose ground, wrong I²C address, or an unsuitable sample rate.

6. Analog sensor or I²C sensor: how would you choose?

Analog can be simple but depends on ADC quality, reference stability and wiring noise. I²C digital sensors often offer selectable ranges, data rates and filters, but require correct bus configuration and logic-level compatibility.

7. What is sensitivity, and how is it different from range?

Sensitivity is output change per unit acceleration (e.g. mV/g or counts/g). Range is the maximum measurable acceleration span before clipping/saturation. Higher range often reduces counts per g for a fixed output format.

8. Why is calibration necessary?

Manufacturing tolerances, mounting, temperature and analog chain errors create bias and scale-factor errors. Calibration estimates offsets and sensitivity; multi-position calibration can also reveal axis misalignment.

9. How would you detect vibration at 80 Hz?

Choose a sample rate above 160 samples/s theoretically, then add practical margin and anti-alias filtering. Confirm sensor bandwidth, data-ready rate, firmware throughput and the frequency response of any digital filter.

10. What does an accelerometer not tell you reliably by itself?

It cannot uniquely distinguish gravity from sustained linear acceleration, and integration of noisy acceleration drifts rapidly when estimating velocity or position. Fuse with gyroscope or other references for robust orientation/navigation.

11. What would you inspect if I²C reads return constant zero?

Check power and common ground, SDA/SCL pins, pull-ups, address and address-selection pin, logic levels, bus speed, register selection, initialization sequence and whether the device acknowledges on the bus.

12. What should be included in a sensor validation report?

Part number and datasheet revision, supply/reference values, mounting orientation, calibration method, sample rate/filter configuration, test conditions, raw and processed data, uncertainty, expected-versus-measured comparison and known limitations.

Industry perspective

In product development, the sensor is only one part of the measurement chain. Engineers define the motion bandwidth and shock range, select the sensor and mounting, design power and bus interfaces, implement calibration/filtering, verify data integrity, and test across temperature and mechanical conditions. A good validation plan records uncertainty and repeatability rather than only showing a plot.

Screen rotation, step counting, wake-on-motion and activity classification.

Common errors and troubleshooting

  • All axes are zero: inspect supply, ground, output pins, bus address and initialization.
  • Values clip: verify range, ADC input limits, sensor output rails and supply voltage.
  • Tilt is reversed: check axis orientation, mounting, sign convention and formula.
  • Readings are noisy: inspect grounding, decoupling, wiring, bandwidth and filtering.
  • Results differ from theory: check sensitivity tolerance, offset, ADC reference, calibration, temperature and whether dynamic acceleration is present.
